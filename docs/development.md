## 本地开发补充

### 前端开发代理的两个必配项

开发态代理有两处**必须显式配**的地方（都在 `vite.config.ts` 里，附原因注释），
少任何一个的表现都是「页面能看，但实时不更新」：

- `ws: true`：不声明的话 Vite 不把 WebSocket 升级交给代理，`/api/admin/live` 永远连不上；
- `headers: { Origin: 'http://127.0.0.1:8888' }`：后端有同源校验
  （`sameOriginOnly` 比 Origin 与 Host），而 `changeOrigin` 只改 Host ——
  浏览器发来的 Origin 仍是 5173，于是**带 Origin 的请求**（WebSocket 握手、
  所有写操作）一律 403。同源 GET 不带 Origin，所以「读」一直是好的，
  很容易被误判成后端的问题。

### 构建后同步产物到后端嵌入目录

```bash
rm -rf backend/internal/web/dist && cp -r frontend/dist backend/internal/web/dist
```

## 实现细节笔记

特性列表只写结论，这里记的是支撑那些结论的取舍与实测。编号引用的「ui-spec
第 N 条」见 `docs/ui-spec.md`。

### 请求日志的筛选语义

- 界面上的「导出」按钮已去掉（2026-09-16），接口 `GET /api/admin/logs/export`
  仍在，需要时直接调它，参数与列表接口完全一致。
- 列表就在**数据看板**页（四张概览卡下面）。它**不吃**上面那组筛选，
  恒定显示**全部最新请求**（2026-09-16 起）—— 列表的用处是盯着最新发生了什么，
  筛过之后反而看不到刚进来的调用，而刚进来的几条恰恰最该被看到。
  筛选用在上面那四张概览卡上：时间范围 / 渠道 / 模型，这三个会**记在本地**，
  刷新或下次打开还是同一个视角，存下来的渠道 / 模型若已被删掉则自动退回「全部」。
- 工具栏上**没有**「筛选只作用于上方卡片」这类作用范围提示（2026-09-17 应站主要求
  移除）—— 列表不吃筛选这件事由契约检查钉住，不再靠界面文案说明。
- trace_id 与「只看失败」这两个排障入口**仍然作用于列表**，但只走 URL：
  `?trace_id=…`（或在日志详情里点「只看这条链路」）与 `?status_class=error`；
  激活时看板工具栏上会出现一个可关闭的小标签。列表顶部的「仅失败」切换按钮
  与「实时 · 最后更新」状态行已于 2026-09-26 应站主要求移除。
  这两个条件是临时的，不跟着记住；而且**带这两个参数的链接不受本机记住的筛选影响**
  （同一个链接发给谁、隔多久打开，看到的都是同一批记录）。
- 旧地址 `/console/logs` 会带着 query 跳到看板，老的链接与书签仍然可用。

### 排序与快速跳页（2026-09-24 加）

耗时 / 费用 / 状态三列点表头即可按服务端排序（`sort=elapsed|cost|status`，
带 `-` 前缀为降序），第三次点击回到「最新在前」。**排序必须由服务端做** ——
前端只能排当前页那 20/50 条，而「最慢的一单」「最贵的一单」显然不在当前页。
费用那一列另有一条口径：站里不做汇率换算，所以后端**先按币种分组、再在组内
按金额排**（`cost_currency` 排在 `estimated_cost` 之前），界面上会同时给出一行说明 ——
否则 `¥2.35` 排到 `$0.0007` 后面会被读成「美元更贵」。分页器另加快速跳页
输入框：25000 条按 20 条一页是 1260 页，只靠 `•••`（一次 5 页）等于到不了
中间那些页。

### 实时推送

- WebSocket 推送看板数值与请求日志，数字用滚动动画过渡、日志插到第一行，
  都不重绘整页。**有新日志时两帧走同一拍**：日志循环查到新行后会立刻叫统计
  循环算一次，所以标记新行的入场动画与卡片数字的滚动是同时开始的
  （从前两者是两个互不相干的定时器，新行先到、数字最多晚两秒，
  见 `docs/ui-spec.md` 第 16 条）。推送本身固定是「今天 + 全站」的视角：
  列表没有额外条件时直接把新行插到第一行；**带 trace / 仅失败深链时则借这个
  推送信号安静地重取一次当前视角** —— 新日志符不符合条件只有服务端知道，
  客户端不去重复实现一遍筛选语义。
- 服务端每 25 秒发一个空的心跳帧（2026-09-24 加）：三条推送都是「变了才推」，
  闲时一帧不发，而客户端的看门狗是「45 秒没收到任何消息就当断开」——
  没有心跳的话，深夜没有流量时一条完全正常的连接会被判成断开并反复重连。
  心跳只证明链路活着，**不代表有新数据**。
- ~~「实时 · 最后更新」状态行移除后，WebSocket 断线仍会自动重连，
  数据停止跳动即是断线的表现。~~（2026-10-11 修正，见下一节：这句话把
  「没有流量」与「连接断了」混成了一件表现，用户无法分辨。）

### 实时连接状态与静默失败（2026-10-11）

上一节最后那条结论是错的，而且错得有代价：断线之后卡片数字、脉搏条、日志列表
**一起**冻住，与「今天真的没流量」在屏幕上完全一样，而脉搏条还会主动说
「暂无流量」—— 把用户引去查渠道和上游，真正的故障在连接上。

现在：

- `useLive.ts` 导出 `liveConnected` / `liveLastMessageAt` / `liveStateOf` /
  `reconnect()`。`liveStateOf` 是纯函数（有单测），三档：
  `live` / `stale`（连着但 35 秒没收到任何帧）/ `offline`。
  **35 秒这个阈值两侧都卡着东西**：必须 > 25 秒（服务端心跳间隔，取小了会让
  一条健康的连接在两次心跳之间反复闪成「无数据」），必须 < 45 秒（看门狗判死的
  时刻，取大了这一档永远看不到）。
- 状态胶囊（`components/LiveStatus.vue`）放在看板脉搏条右侧，`role=status` +
  `aria-live=polite`（「数字停止跳动」这条线索对读屏用户不存在）。
  断线时给一个「重试」按钮 —— 退避最坏要等 15 秒，而用户点重试的意思是「现在」。
- 胶囊**只说连接状态，不说数据新鲜度**。服务端 25 秒一次心跳，所以「最后一帧」
  的年龄会稳定地每 25 秒推进一次；把它显示成「数据 N 秒前更新」是在说假话。
- `useLive` 新增 `visibilitychange` / `online` 抢救：后台标签页里浏览器会把定时器
  节流到分钟级，45 秒的看门狗因此不按时跑，切回来时界面可能还停在「已连接」上。
  回前台 / 网络恢复时按「多久没收到帧」重新判断一次。
- 脉搏条加断线档（斜纹底轨），`title` 不再说「暂无流量」；日志面板空表在断线时
  改说「实时连接已断开，暂时看不到新记录」—— 原来的文案会让用户去查渠道。
- **静默重取失败要留痕**：实时推送触发的重取（`silent`）以前把错误整个吞掉。
  一次抖动确实不该弹提示，但**连续**失败是另一回事：屏幕上的数字会一直停在
  几分钟前，看起来却和「刚刷新过」一样。现在连续 3 次失败就把 `loadError`
  写进去，直接复用 `DataState` 现成的「顶部告警 + 保留数据 + 重试」分支，
  并加 10 分钟限流（持续失败时每秒弹一次比不提示更烦）。取数成功时同时
  清零计数并**清掉 `loadError`** —— 原来只在非静默请求开始时清，
  于是静默重取成功之后那条红色告警会一直粘在表格上方。

### 实时插行必须尊重当前排序（2026-10-11 修）

`sort`（耗时/费用/状态，服务端排序）原来**不在** `onLive('logs')` 的守卫里：
排序生效时新日志照样被 unshift 到第一行，「耗时降序」当场失效。更糟的是排序偏好
是持久化的（`log-sort`），刷新页面后错序还在 —— 用户只会觉得这个排序坏了。

判据抽成 `components/logLive.ts` 的 `decideLiveInsert`（纯函数 + 单测），
三种处置：

- `insert`：无深链、无排序、在第 1 页 → 直接插到第一行（默认视角，列表存在的理由）；
- `reload`：有深链条件**或**有排序 → 按当前视角静默重取（深链那一支的理由：
  新日志符不符合条件只有服务端知道）；
- `count`：第 1 页之外 → 只累计并显示「有 N 条新日志，回第 1 页查看」。
  新行按定义属于第 1 页，插进第 3 页只会让这一页错位；但完全不提示又会让人
  以为「翻页之后就没有新请求了」。回到第 1 页（点提示条或点分页器）即清零。

判据的优先级是深链/排序先于页码：它们改的是**取数条件本身**，无论在第几页，
唯一正确的处置都是按当前条件重取。

### 渲染异常不再是一张空白页（2026-10-11）

全仓此前没有任何 `errorHandler` / `onErrorCaptured`。这里有一条**反直觉**的事实，
值得记下来，因为它是这一整节存在的前提：

> Vue 3 对渲染期异常的处理不是「卸载整棵树」，而是**中止这一次渲染、其余照旧**
> （`handleError` 记一笔，然后继续）。所以一个叶子组件的渲染异常不会白屏 ——
> 它只是**静默地少渲染了一块**，而且没人知道。

这条事实决定了两件事：

1. **必须要有边界。** 「半坏的界面」比「明确说坏了」更危险：用户看着一张
   少了内容的表格，会以为数据就是这样。`components/ErrorBoundary.vue` 把错误
   换成一块带「重新加载 / 复制错误信息 / 回到数据看板」的面板。放**两层**：
   - `App.vue` 里一层（兜外壳本身的错误、以及登录页）；
   - `MainLayout.vue` 的 `<router-view>` 外面一层（页面级）——
     页面坏了的时候侧栏还在，用户可以点别的菜单走开，而不是只能刷新。
     两层嵌套时内层先接住（`onErrorCaptured` 返回 `false` 就不再向上冒泡）。
   边界只在**换页时**复位（`route.fullPath` 变化），不提供「原地重试」：
   渲染异常几乎都源自拿到手的坏数据，原地重试通常会再炸一次。
2. **它会把你一直藏着的 bug 照出来。** 这一点是实测的：加上边界之后看板整页
   变成了错误面板，而在此之前 W1 那批用例全绿 —— 因为 DailyReport 里的
   `report.summary.requests` 在响应缺字段时抛异常，而 Vue 把它吞了，
   只停掉战报那一次的渲染。**边界把一个静默降级变成了可见故障**，
   这是它最大的价值，也是加它之后必须立刻跟着修的地方：
   战报现在赋值前先校验形状（不合规就当「拉不到」，安静地不弹 ——
   那本来就是它自己的契约），见 `components/DailyReport.vue`。

边界之外还有两层：

- `app.config.errorHandler`（`main.ts`）：只记录 + 一条 `message`，
  不做界面恢复（那是边界的职责）。用 `utils/feedback` 的实例而不是 antd 静态
  方法 —— 静态方法拿不到 ConfigProvider 的主题上下文，深色主题下会弹白底气泡。
- `router.onError`：只处理「懒加载 chunk 取不到」（用消息特征判断，
  `NavigationFailure` 不带错误类型），因为它的表现是**点了菜单没反应** ——
  界面停在原页、控制台里一句 ChunkLoadError，用户完全不知道刷新就能好。
  其余导航错误照旧抛出：吞掉未知错误只会让真正的 bug 更难查。

回归：`.shots/verify-ux-2026-10-11.mjs` 的 E1 组用**真实的渲染异常**验证
（让桩接口返回一条 `null` 日志，表格的 `rowClassName` 因此炸在渲染期），
不是模拟。

### 日志表：首屏就渲染表头（2026-10-11）

原来 `DataState` 的 loading 档会在首屏把整张表换成一个居中的转圈面板，
数据到了才渲染表头与表体 —— 那一刻表格从「一个转圈」变成「39px 表头 + N 行」，
高度突变、下方内容整体下移，而列宽还要等首帧渲染完才有测量对象。

现在表格从第一帧就在（表头立刻可见、列宽有量测对象），空的表体由 antd 自己的
loading 转圈表达；`DataState` 在这张面板里只留「失败」与「空态」两档。
`:loading="false"` 是**有意**传的，不是漏传 —— 这一点写在了模板注释里，
否则下一个人会「顺手修好」它。

配套的是 `#emptyText` 的分支：加载中**不显示空态文案**。因为「还没有请求日志」
是一个**结论**，而结论要等取数回来才能下。这个职责原来由 DataState 的 loading 档
挡着，现在落到 emptyText 上。

### 列宽：实时插行只量新行（2026-10-11）

整页量一次是「行数 × 列数」次 `getBoundingClientRect` —— 50 行 × 10 列 = 500 次
强制布局，而直播高峰每秒都能推进来一批。一秒 500 次强制布局在低配设备上是
肉眼可见的卡。

增量路径只读新插入的那几行（通常 1–2 行 × 10 列 = 10–20 次），差两个数量级。
宽度不会被「量窄」：`measuredW` 里留着这一页已量到的**内容宽**，增量结果与它
取大者，所以列宽仍然只增不减，直到下一次全量测量（翻页 / 换筛选 / 列显隐变化）
重置累计。两处必须一起改，只做增量会让一条窄内容把列宽缩回去。

两个细节：

- 增量与全量的选择器必须不同：增量时 root 是 `<tr>`，
  `tr.querySelectorAll('.ant-table-tbody X')` 会在这一行**内部**找一个 tbody
  后代，永远查不到。
- 后台标签页里不量（不做布局、用户也看不见），改为记一个标记，
  回到前台时全量量一次 —— 否则后台期间插进来的行永远不参与列宽。

### 翻页 / 排序之后回到列表顶部（2026-10-11）

滚动条原来停在原处，而第 2 页第 30 行与第 1 页第 30 行是两个完全不同的位置 ——
用户点「下一页」时看到的是表格中段，会以为列表没换（尤其是行数相同、
只有数字变了的时候）。换每页条数同理，而且换条数后原来那个 `scrollTop`
常常越界，浏览器会把它夹到新底部，落点更随机。

滚的是 `.ant-table-body` 而不是窗口：这张表有自己的纵向滚动（面板锁高、
表体吃剩余高度），窗口根本没滚动过。

### 详情抽屉可以分享了：?log=&lt;id&gt;（2026-10-11）

站内此前唯一的「把一条请求发给别人看」的方式是截屏或口述「第 3 行那个」，
而排障常常是两个人一起看 —— 列表又不吃筛选条件，「第 3 行」换个时间打开
就不是同一条了。

URL 由**看板**持有（与 `trace_id` / `status_class` 同类），面板通过
`logId` prop + `update:logId` 事件参与。三级降级：

1. 在本页行里找（绝大多数情况，零请求）；
2. 找不到就请求 `/logs/:id` —— 那个接口一直都在
   （`backend/internal/api/admin.go` 的 `logDetail`），只是界面上唯一的入口是
   「从列表点开」，于是从没被前端用过；
3. 拉不到（不存在 / 已过保留期）就说清楚并清掉 URL 参数。**不静默失败**：
   用户是点了别人给的链接来的，什么都不发生会让人以为链接坏了。

抽屉里按 ↑ / ↓ 换记录时 URL 跟着换、关闭时清掉 —— 否则刷新页面会打开**另一条**
（或抽屉又弹回来，像是关不掉）。写 URL 用 `replace` 而不是 `push`：
连看十条不该在历史里留下十条。

### 导出按钮回到看板工具栏（2026-10-11）

站主 2026-09-16 把导出从**日志面板**撤掉，理由是那张面板的 40px 标题栏整个要删
（表体刚好能多放一整行）。现在它回到**看板工具栏**、做成图标 —— 与刷新、
列设置、主题并列，不占表格面板的高度，也不给那张面板加回标题栏。

参数由面板 `defineExpose` 的 `exportQuery()` 提供（与列表**同一份**条件，
只去掉分页）。不这么做的话，两处各写一遍参数迟早漂移，而漂移的表现是
「列表里 12 条、导出 3400 条」—— 没人会立刻发现。下载走一个临时 `<a>`：
不用 `window.open`（会被当成弹窗拦掉），也不用 fetch + blob
（几万行 CSV 全进内存，还要自己解析 `Content-Disposition` 里的文件名）。

### 分享一个「视角」而不只是地址（2026-10-11）

工具栏筛选项（时间范围 / 分组 / 模型）**变化时不写地址栏**：每变一次就往历史里
塞一条，返回键会变成「上一个筛选」而不是「上一个页面」。但「复制当前视角链接」
会显式把它们带上，所以 `applyUrlFilters` 必须读它们 —— 否则复制出去的链接打开后
是另一个视角，而收链接的人无从察觉。两条规则不矛盾：

- 自动写入（`syncUrl`）：只有排障深链（trace_id / status_class / log）；
- 显式分享（`copyViewLink`）：深链 + 三个筛选，**并且**读取端支持。

### 四张管理表的本地搜索与分页（2026-10-11）

`/channels`、`/keys`、`/groups`、`/proxies` 四个列表接口都是**一次返回全量**
（没有 page / page_size，密钥那条接口的 total 就是 `len(items)`）。这是有意的：
数据量级是几十到几百条，后端加了分页也不会让任何一次请求变快（一次全表扫描
vs 一次带 offset 的全表扫描）。但界面上不处理的话，一屏几十行仍要滚，
而「按名字找一个渠道」在 200 个渠道里靠眼睛扫是最慢的方式。

判据抽成 `components/tableTools.ts`（纯函数 + 17 条单测），响应式接线在
`composables/useTableTools.ts`。**分页最容易错的两处**都在纯函数里钉住了：

- 搜索后没回第 1 页 —— 停在第 5 页搜出来的东西通常不足一页，不回去就是一张空表；
- 数据变少后当前页越界 —— 夹页放在 `computed` 里而不是 `watch` 里写 `page`：
  watch 是渲染之后才跑的，中间那一帧表格是空的（搜索时肉眼可见地闪一下）。

只有一页时不渲染分页条（默认数据量常常不足一页，底部常驻一条「共 3 条」
既占高度又没有信息量）。

**搜索无结果 ≠ 一条数据都没有**：前者给「清空搜索」，后者才是「新建」。
四张表的空态都分了这两支 —— 给错的话用户会去新建一个同名渠道，
而他要找的那个其实就在库里。

### 分页或搜索生效时锁住渠道拖拽排序（2026-10-11）

这一条是**数据完整性**问题，不是显示问题，所以单独记。

渠道列表的顺序就是故障转移顺序，而拖拽提交的是从 DOM 读出来的**整组顺序**
（`onDragEnd` 的 `domOrderedIds`）。屏幕上只有一部分行时（搜索命中 3 条、
或者分页只显示第 1 页），提交上去的就是一个子集：后端把这几条重排成 1..N，
没显示的那些还留着旧序号 —— **整组顺序乱掉，而且没有任何报错**。

`useTableTools` 因此额外返回 `isSplit`（有搜索词、或数据多到分了页），
渠道页在 `isSplit` 时**不渲染拖拽手柄**，原位给一个锁定图标 + tooltip 说明
（「清空搜索、或把每页条数调到装得下全部渠道即可恢复」）。键盘调序挂在同一个
手柄上，所以两者一起关掉。`onDragEnd` 与 `moveChannel` 里各留了一道
「真到了这里就回弹」的闸 —— 手柄不渲染是第一道，但它们不该是唯一一道。

判定只能有一个出处：这条规则关系到数据会不会被改坏。

### 批量启停：作用在「当前筛选结果」上（2026-10-11）

第一版做的是勾选列 + 「已选 N 项」。放弃它的原因是**宽度**：勾选列要占 32px，
而渠道表各列声明宽之和 1177 在 1440 视口下正好等于容器宽（1182）——
多出来的 32px 会让这一页重新出现横向滚动条，而 `scripts/check-table-widths.mjs`
**查不出这件事**（它只比对「声明宽之和 ≤ scroll.x」，勾选列不在声明列里）。
要腾出 32px 只能压某一列的内容宽，而「每列至少把内容显示完整」是站主
明确定过的要求。为一个批量入口去动列宽，代价比收益大。

「作用于当前筛选结果」反而更贴合真实用法：某个上游出问题时的动线是
「按模型 / 地址搜出这一批 → 一起停掉」—— 搜索框已经把这个集合描述清楚了，
再让人去勾 20 个复选框是多余的一步。代价是**必须说清作用范围**：
按钮上写着数量（「批量停用 7 个」）、确认框里重复一遍当前的筛选条件。
停用走确认、启用不走 —— 启用的后果是「这批重新接活」，弄错了再停一次即可；
而停用会让正在用的客户端当场报错。

实现在 `composables/useBatchToggle.ts`，两页共用。三条设计：

- **顺序跑，不 `Promise.all`**：每条都是一次写库，几十个并行 PUT 只会排队；
  失败时要能说清哪几条没成功，并行回来顺序是乱的；而且「正在处理 7/20」
  比一个不知道要转多久的转圈强得多。
- **失败不中断**：中途某条 400/409 时继续跑剩下的，最后一次性汇报失败名单。
  中断的话「已成功 7 条」这个事实既没被说出来、剩下的也没做 —— 用户面对的是
  半成品状态，而他不知道是哪一半。
- **复用单条接口**：批量不是一条新的写路径，只是把同一件事做很多次。

### 每分钟上限：从 modal.confirm 改成真表单（2026-10-11）

原来这里是 `modal.confirm` + `h(InputNumber)`，有两个绕不过去的坑：

1. **校验不过时 `onOk` 无处可去。** 返回 resolved 会**关掉弹窗**
   （用户刚敲的数字白填）；返回 rejected 则要读 antd 的实现才知道它
   「不关闭、按钮复位」，而且它会把拒绝继续抛出去
   （`es/_util/ActionButton.js:74`）—— 控制台每次多一条未处理的 Promise 拒绝。
   返回一个永不 settle 的 promise 更糟：按钮会永远转圈
   （loading 只在 `then`/`catch` 里复位）。
2. **服务端错误没地方放**，只能弹一条顶部 message，用户看不出是哪一格错了。

换成 `a-modal` + `a-form` 之后：规则写在 `rules` 里、错误显示在输入框正下方、
提交前先 `validate()`、服务端错误挂到同一个字段上（`:help` + `validate-status`）。
这也是全站其它表单一直在用的做法。

顺带修了同一页的启停并发：连点两下会发两次「切成 `!row.enabled`」——
两次载荷完全相同，于是开关看起来「点了没反应」。现在按行加锁 + `loading`，
锁的是**这一行**而不是整表。

### 密钥明文缓存会过期、切走即丢（2026-10-11）

「悬停看全量」的明文原来是**永不过期**的一份映射：鼠标从列表上扫过之后，
那把密钥的明文就一直在 JS 内存里躺到这个标签页关闭为止。两个问题：

1. **机密性**：共享屏幕、录屏、或者别人接手这台机器时打开 DevTools，
   都能从内存里读到已经不再显示在屏幕上的明文。缓存本来只是为了让
   「悬停 → 点击复制」不重复解密，这个理由撑不起「一直留着」。
2. **正确性**：密钥在别处轮换过之后，界面还在拿旧明文 —— 用户复制走、
   粘进客户端、调用失败，而界面上「看起来」是好的。

现在两个出口：**60 秒 TTL**（够完成「看一眼 → 复制」这个动作），
以及**页面一切走就全部丢掉**（`visibilitychange` → hidden，切标签 / 最小化 /
锁屏都会触发）。离开这一页（`onUnmounted`）也丢。

另外给显示明文的 tooltip 加了 `destroy-tooltip-on-hide`：antd 默认把提示的 DOM
留在页面上（只是隐藏），于是「悬停看过一次」的全量明文会一直躺在 DOM 里 ——
打开 DevTools 就能读到，而屏幕上什么都没有。

### 白名单删除可撤销（2026-10-11）

一行白名单可能包含刚手工录入的一整组单价（输入 / 输出 / 缓存读 / 缓存写，
还能带按时段倍率），删掉之后**没有任何地方能找回**。而一个「确认删除」弹窗在
连续录入的场景里很快就变成无脑回车（用户会条件反射地按下确定）。

现在删掉之后在动作区出现「已删除「模型名」，撤销」，3 秒窗口。撤销恢复的是
**整行快照**（含单价、时段倍率、代理）并按原下标插回 —— 白名单的顺序就是列表
顺序，用户按那个顺序读它。同一时刻只留一个撤销入口：连删两行时第一行的撤销
会被第二行顶掉，这是有意的 —— 保留一摞撤销栈会让「撤销」这个按钮的语义
变得不确定。

### 刷新 / 关标签页也拦住未保存的改动（2026-10-11）

`useDirtyClose` 原来只覆盖**弹窗内**的关闭路径。用户填了十个字段之后直接按 F5
或关掉标签页，浏览器不问、页面也不问 —— 内容一个字节都不留。那是同一个损失的
另一半。现在这个 composable 顺手挂一个 `beforeunload`，**六个调用点一起获益**。

两条浏览器限制：文案不能自定义；Chrome 要求页面**有过用户交互**才真的弹
（所以「打开看一眼就走」不会被拦，那也正是我们想要的）。判定直接调 `isDirty()`
而不是维护一个额外的 ref —— 它本来就是「现在和基线比」，而 `beforeunload`
在真的要离开时只触发一次。

### 窄屏列预设与侧栏形态记忆（2026-10-11）

- **列预设**：日志表 10 列在 1440 下正好铺满，而 ≤900px（侧栏收成图标栏那一档）
  可视宽度只剩 1000 出头 —— 一进页面就要横向拖。现在窄屏且**用户从未调整过**
  列显隐时，默认收起「速度 / 费用 / 密钥」三列（排障视角里第二眼的问题），
  留下模型、渠道、词元、耗时、状态。用 `applyPresetOnce` 记一个标记：
  用户自己调过就不动他的设置，`reset()` 之后也不会被重新套上。
  放在 `logColumnVisibility.ts` 的模块作用域执行 —— 它就是「首次读
  localStorage 之前定下初值」，晚一拍就会先渲染一遍全列再收起来。
- **侧栏形态**：常用图标栏的人每次刷新都要再收一次。现在记在 localStorage 里，
  规则分两层：窄屏一律收起（硬规则），宽屏用记下来的偏好。
  断点**自动**引起的变化不写偏好 —— 否则「在窄屏下自动收起」会把用户在宽屏下
  选过的展开态覆盖掉。这一条靠一个 `autoCollapse` 标记区分，并在
  「值没变就提前返回」时注意别把标记留下（那会让下一次手动点击被吞掉）。
- **图标栏里的版本入口**：收起态原来整块不渲染 `VersionBadge`，于是
  「有没有新版本」「能不能一键更新」在 56px 形态下**完全没有入口**，
  而更新提示正是用户需要知道的信息。`VersionBadge` 现在支持 `icon-only`，
  面板与逻辑完全共用；展开态不渲染它（同一信息不该在侧栏里出现两次）。

### 全站快捷键（2026-10-11）

站主的日常动线是「看板 → 找那条报错 → 去渠道页改 → 回来看」，每一步都要先用
鼠标找到侧栏再点一下。三组快捷键：

| 键 | 动作 |
|---|---|
| `/` | 聚焦当前页的搜索框 |
| `r` | 刷新当前页（合成一次点击，与手点完全同一条路径） |
| `g` 然后 `d/k/c/f/p/s` | 看板 / 密钥 / 渠道 / 分组 / 代理 / 系统设置 |

三条约束，每一条都是「不做会出事」的：

1. **焦点在输入框 / 文本域 / 下拉 / 可编辑区里时一律不拦。** 否则用户在搜索框里
   打「r」会被抢去刷新，而这个 r 还打不进去 —— 这是快捷键最经典的破坏方式。
2. **带修饰键的组合不处理**：Ctrl+R 是浏览器刷新，抢过来会让用户觉得
   「这个页面把浏览器弄坏了」。
3. **序列键只等 1.5 秒**，期间按了别的键就当场作废。

页面上没有搜索框 / 刷新按钮时**不 `preventDefault`**：抢掉一个按键却没有任何
反馈，用户会以为页面卡了。可发现性靠 `aria-keyshortcuts` 与按钮的
`title="刷新（快捷键 R）"`。

### 渠道 API Key 那一格（2026-10-11）

- **`has_api_key` 这个后端字段不需要加。** 原计划是「后端加一个字段说明
  这条渠道有没有配密钥」，动手前先读了一遍接口 —— 列表接口本来就下发
  `api_key_hint`（`secure.MaskKey` 的产物，形如 `sk-abc...wxyz`），
  而且它只在真正保存过密钥时才被写入（`admin.go:743-751`，留空表示不修改）。
  所以 `!!api_key_hint` 就能回答那个问题，加字段等于把同一个事实存两遍，
  而两份事实迟早会不一致。前端现在把掩码写进标签：
  「API Key（已保存 sk-abc...wxyz，留空表示不修改）」。
- **`autocomplete="new-password"`**：那是一个 `type=password` 的输入框，
  浏览器与密码管理器会把它当成「登录密码」并主动提供自动填充 ——
  在这台机器上存过管理台登录凭据的用户，打开这个表单会被填进一段无关的密码，
  而他很可能不会逐字符核对就保存了。`new-password` 是浏览器唯一可靠地
  「不自动填充历史值」的取值（password 字段上的 `autocomplete="off"` 会被
  Chrome 忽略）。`name` 也起了一个不像登录表单的名字。
- **占位符不再写 `sk-...`**：那句是从 OpenAI 的文档里抄来的，而这里要填的是
  **任意上游**的密钥 —— Anthropic 的 `sk-ant-`、Gemini 的 `AIza`、
  国内厂商的各种前缀，写 `sk-` 会让第一次配 Anthropic 的人怀疑自己贴错了地方。
- **测试连通性弹窗加 `mask-closable="false"`**，且测试进行中禁用 Esc：
  弹窗里用户已经选好了模型、可能还敲了一段提示词，点到遮罩上就整个丢掉，
  而遮罩是屏幕上一大片区域。测试中关掉弹窗会让「正在测」的进度消失，
  而请求还在跑，几秒后突然弹出一个结果框，用户已经不记得自己点过什么了。
  测试结束后 Esc 恢复 ——「测试中不许退出」不等于「这个弹窗关不掉」。
- **`has-data` 用未筛选的行数**：原来传的是 `visibleRows.length`，
  于是「筛到一个空分组」被 `DataState` 当成「一条数据都没有」，
  给出的是它自己的空态面板，而不是表格自带的（更准确的）
  「这个分组下还没有渠道，可以切换分组筛选看看」。筛选是**视图**，
  不是数据有没有来；这两件事必须分开。

### 日志表的行密度（2026-10-11）

一屏能看多少行是这张表最直接的取舍：行高 44px 时表体里是 13.4 行，39px 时
15.2 行（1440 视口实测）。开关放在**列设置弹层**里（与列显隐同属「这张表怎么看」），
不在工具栏再加一枚按钮 —— 那里已经有 6 件东西了。

`compact` 只收单元格的上下内边距（8px → 3px）。**为什么不动行高本身**：
`--size-table-row` 只是**声明**高度（39px），实际高度由内容决定 ——
词元那一格是上下两排共用一个网格（`.token-cell` 实测 30px），

### 模板组件的引入完整性（2026-10-11，契约脚本）

组件在这个仓库里是**逐文件 import** 的（只有 `main.ts` 里那 20 来个 antd 组件
是全局注册的），而 `vue-tsc` **不检查模板里的未知标签** —— 漏一个 import 的表现是
「控制台一条 `Failed to resolve component` 警告 + 那一块渲染不出来（或只剩文字）」，
而 type-check、契约检查、列宽守卫**全都照过**。

这一批里真的漏了两处（渠道页的两枚批量图标、代理页的 `EmptyState`），
是代码审查抓出来的 —— 那就该有一条脚本管着。`npm run check` 现在多一条
「模板组件的引入完整性」：扫每个 `.vue` 的 `<template>` 段里所有大写开头的标签，
要求它在本文件的 import 绑定里、或在 `main.ts` 的全局注册表里、或是 Vue 内置
（`Transition` / `KeepAlive` 等）。反向验证做过：注掉一个 import 之后它确实报红。

两个实现细节（第一版都踩了）：

- import 列表里允许写注释（本仓库的惯例就是在那一行说明「这枚图标是干什么的」），
  所以解析前要先 `stripComments` —— 否则注释文字会被当成标识符，
  报出来一屏假阳性（明明 import 了却说没引入）。
- 默认导入、命名导入、以及两者混写（`import X, { a } from`）都要认；
  第一版的正则只覆盖了命名导入，于是三十来个默认导入的组件全被误报。

### 有意没做的一件（2026-10-11，留档）

**日志列宽手动拖拽**。两个理由，第一个是设计上的，第二个是验证上的：

1. **它与这张表已经确立的两条规则冲突。** 列宽由 `distribute()` 按容器余量均摊，
   而各列宽度是 `remeasureColumns` 按**本页实际内容**量出来的 ——
   站主 2026-09-23 明确要求过「每列至少把内容显示完整」，那正是这套自适应的目的。
   手拖一个宽度进去，下一次实时插行／翻页就会把它覆盖掉；要让它成立，
   得先定义「固定宽度」与「自适应宽度」的优先级、持久化格式、以及
   「用户拖窄到看不全内容之后算谁的」—— 这是一个独立的设计问题
   （工单式的「这一列我固定住」vs 全局的「按内容自适应」），
   不该在收尾时顺手塞进去。
2. **更省事的替代已经存在**：想少看一列就**关掉它**（列显隐 2026-10-10 上线，
   持久化、带锁定列保护），想多看几行就切密度（上面那一节）。
   手拖列宽能解决的问题，这两件事已经覆盖了大部分。

真要做的话，还得让 `scripts/check-log-columns.mjs` 的逐格完整性检查接受
第二种宽度来源，并对着真实数据复验（要带鉴权的后端）—— 留给下一轮。
记录在此是因为「没做」和「忘了做」在文档里的价值完全不同。

### 内容区滚动位置在换页时重置（2026-10-11）

滚动容器是 `.console-content`（`overflow: auto`），而它跨路由复用 ——
只有 `<router-view>` 里的内容换。全仓没有任何地方重置过它，router 的
`scrollBehavior` 也不管用（它作用于文档滚动）。后果：从滚到底的「系统设置」
切到「渠道管理」会落在新页中段（浏览器只会把 `scrollTop` 夹到新页的最大值）。

现在在 `MainLayout` 监听 `route.path` 时置 0。**只在 path 变化时**：
query-only 的变化（`?trace_id=` 这类排障深链）是「同一个页面换个视角」，
把用户正在看的位置弹回顶部反而更烦。本批不做历史滚动恢复（前进/后退也按
path 变化处理）。

### 弹层的键盘可达性（2026-10-11）

三个 antd 弹层（看板主题选择、侧栏版本面板、工具栏列设置）原来各缺一角：
焦点进不去（内容 teleport 到 body，触发按钮的焦点不跟着走）、Esc 关不掉
（全仓只有移动端抽屉处理了 Esc）、关闭后焦点掉回 body（下一次 Tab 从页面最顶上
重来）。抽成 `composables/usePopoverA11y.ts`（打开移焦 / Esc 关闭 / 关闭还焦），
三处共用 —— 抄三遍的结果必然是「一处忘了还焦点、一处没有 Esc」。

关闭时**只在焦点确实孤悬**（在弹层里、或已经掉到 body）才把焦点还给触发按钮：
用户点了弹层外面别的东西而关闭时，焦点正落在那个东西上，抢回触发按钮等于把
用户刚点的目标顶掉。

`preferred`（打开后优先聚焦哪个控件）是**偏好而不是硬要求**：它可能指向一个
聚焦不了的东西，这时要退到「第一个可聚焦控件」。这不是防御性代码 ——
列设置传的 `preferred` 一开始指向第一个勾选框，而日志表的第一列（请求时间）
是**锁定列**、勾选框是 `disabled`：焦点于是永远停在 body，连 Esc 都跟着失效
（`onKeydown` 要求事件目标落在弹层里，焦点不在弹层内就不成立），弹层只能靠
再点一次触发按钮关掉。现在 `preferred` 写成 `.cs-item input:not([disabled])`，
composable 里也补了聚焦失败后的兜底。

### 破坏性确认默认不聚焦危险按钮（2026-10-11）

antd 的 `autoFocusButton` 默认是 `'ok'`（见 `es/modal/ConfirmDialog.js`），
而全站 7 处 `modal.confirm` 全是破坏性动作（删渠道/密钥/分组/代理、清空单价、
放弃未保存改动）。焦点落在危险按钮上意味着：键盘用户「回车触发行内删除图标 →
再一次回车」就完成了删除，按住回车也会直接删掉。

在 `utils/feedback.ts` 的 `modal.confirm` 里统一注入默认
`autoFocusButton: 'cancel'` —— 该文件已是全站唯一出口，一处改动覆盖 7 个调用点。
调用方显式传值时不覆盖：密钥页的「修改每分钟上限」弹窗传 `null`
（它的目的是填一个数字，焦点该在输入框里）。

### 行级操作后的焦点归还（2026-10-11）

渠道 / 密钥 / 代理三页的动作成功后都是整表重拉，而 antd 的
`focusTriggerAfterClose` 想把焦点还给触发按钮时，那个按钮已经随旧行销毁 ——
焦点掉回 body，键盘用户要重新从页面顶部 Tab 一长串（列表越长代价越大），
读屏用户还额外失去「现在在哪一行」的上下文。

`utils/focusRow.ts` 按 `tr[data-row-key]`（行的身份）+
按钮 `aria-label` 前缀（动作名）找回同一行的同一个动作；行不存在（多半就是刚删掉
的那一行）时焦点落到表格容器上 —— 容器带 `tabindex="-1"`，焦点仍在「这一块」里。

顺带补了渠道启用开关的 `aria-label`：antd 的 Switch 渲染成
`<button role="switch">`，没有可访问名时读屏只会念「开关，已开启」。
名字**不随状态变**（不写「启用/停用 X」）—— 开关的语义是 `role=switch` +
`aria-checked`，名字描述的是「这个控件管什么」；名字随状态变会让读屏在切换后
念出一个不同的控件名，用户以为是另一个开关。

### 日志表的键盘模型（2026-10-11）

原来唯一的入口是「操作」列那枚图标按钮，而一页有 20/50/100 行 ——
打开第 40 行的详情要按 40 次 Tab。现在用 **roving tabindex**：
整张表在 Tab 序里只占一个停靠点（当前行 `tabindex=0`，其余 `-1`），
进入后 ↑ / ↓ 换行、回车开详情。这是网格/列表类控件的标准键盘模型，
也是「一屏可聚焦控件数量」不随数据量增长的关键。

**「只占一个停靠点」这句话要成立，行内那枚「详情」按钮必须一起移出 Tab 序**
（给它 `tabindex="-1"`）。只把 `<tr>` 做成 roving 是不够的：按钮仍是普通
`button`、仍按 DOM 顺序进 Tab 序，一页 100 行就是 104 个停靠点。
这一点是代码审查实测出来的（当时表内实测 24 个停靠点 = 3 个可排序表头 +
1 个 `tabindex=0` 的行 + 20 枚按钮），而当时的验收断言只统计
`tr[tabindex="0"]` 的个数，所以一直是绿的 —— 断言的口径必须覆盖**整张表体**里
所有 `tabIndex >= 0` 的元素，只数行是测不出这个漏的。
按钮设成 `-1` 之后仍可点击、仍能被读屏的虚拟光标读到（`aria-label` 还在），
只是不再参与 Tab 走查：键盘路径由行负责。

两处配套：

- 行获得焦点时的环画在**行内**（`outline-offset: -2px`）。全站那条
  `:focus-visible` 用正 offset（画在元素外面），对按钮是对的，对表格行会压住
  上下相邻的行，看起来像两行都被选中了。
- 详情抽屉给「上一条 / 下一条」按钮并支持 ↑ / ↓（排障的常态是连着看几条，
  原来每看一条都要关掉、回列表、重新找）。监听挂在 `document` 上而不是抽屉内容上：
  焦点进抽屉时落在 antd 的容器上，内容里的元素不是它的祖先。
  抽屉标题也从固定的「调用详情」改成「时间 · 模型」。

### 窄屏的页名与路由播报（2026-10-11）

≤900px 侧栏收成图标栏、菜单文字全部隐藏，而页面标题是 `sr-only` 的 `<h1>` ——
641–900px 的用户除了浏览器标签标题之外没有任何「当前在哪一页」的线索。
现在图标栏形态下在内容区顶部渲染一行小号页名；≤640px 的移动端顶栏把品牌名
换成当前页名（品牌名在标签栏与登录页都有，重复它等于浪费手机上最宝贵的一行）。

另加一个 `aria-live` 的路由播报（「已进入 数据看板」）：SPA 换页浏览器不会像
多页应用那样自动播报新页面，读屏用户停在原处只能自己按标题跳转去确认。
只在**真的换了 path** 时写（首屏不播、query-only 变化不播）。

### 渠道优先级支持键盘调整（2026-10-11）

列表顺序就是故障转移顺序，而调整入口原来只有 SortableJS 的拖拽 ——
纯键盘与读屏用户完全没有调整入口（WCAG 2.1.1）。现在拖拽手柄是 `<button>`
（SortableJS 认的是 `.drag-handle` 这个类名，换标签不影响拖拽），
Tab 能聚焦、聚焦后按 ↑ / ↓ 调序，提交走与拖拽**完全相同**的
`submitOrder(groupID, orderedIds)` 链路，后端零改动。

组内顺序按 `(weight, id)` 排，与 `visibleRows` 的排序键逐字一致 ——
少了 `id` 那一档时，两条 weight 相同的渠道会得到不确定的次序，
上移/下移于是可能「移不动」或跳两格。

### 首屏形状：骨架卡而不是转圈（2026-10-11）

看板首屏原来是 `DataState` 的「转圈面板」，而四张卡与日志面板是**兄弟节点** ——
日志面板先取数成功，卡片随后整块长出，把表格往下推 90–150px 并触发一次列宽重测。
现在 `DataState` 支持可选的 `#loading` 插槽，看板传四张 `StatCard loading`
（骨架条与真数值同高同行），首屏形状 = 加载完成形状。

同一批还修了「零值假象」：`summary === null` 时页面原来已经写着
「失败 0 次」「命中率 0.0%」「平均首字耗时 0ms」（`?? 0` 的产物），
三条都是错误结论，而它们看起来和真实数据完全一样。现在没数据时一律显示「—」。
`AnimatedNumber` 也加了一条判据：**上一帧是空值就直接落值、不补间** ——
否则金额卡会从 ¥0.0000 滚到真值，看起来像钱从 0 开始涨。


### 新日志直接进列表（2026-09-25 改回）

实时推送带来的新行一律插到第一行，不等待任何交互。此前有过一版「挂起」机制
（9e9f3b4，P1-6）：表体滚过中段、鼠标停在表体上、或详情抽屉开着时把新行攒起来，
表格上方显示「有 N 条新日志，点击查看」。它的判据里「鼠标停在表体上」在真实
使用中几乎是常驻状态（正看着某一行、或在等新行出现），而释放只发生在滚动 /
鼠标移出 / 抽屉关闭三个时刻，于是新行只攒不落、列表看起来冻住了 —— 站主反馈
「只显示提示，但是列表不更新，鼠标动一下才更新」。

（2026-10-11 补：这只在**第 1 页且无排序、无深链**时成立。排序生效时新行会被
unshift 到最前面、静默破坏排序，第 1 页之外则只计数并提示「回第 1 页查看」——
见上面「实时插行必须尊重当前排序」一节。`count` 那一档**不是**把当年那套挂起
机制改回来：它只在「用户看的本来就不是最新那一批」时提示，列表不会冻住。）

新行插到头部必然让内容下移一行（这是「最新在最上面」的定义），位置稳定由
前端自己用 JS 显式做：插行前量出「视口里第一个可见行」相对表体顶部的偏移，
插行后按差值补 `scrollTop`，那一行就仍停在原处（只在用户已经滚动过时补偿；
停在顶部时用户要看的正是刚进来的几条）。**不依赖浏览器的原生滚动锚定**：
实测（2026-09-25）Chrome 的 `overflow-anchor` 在最小页面上有效，在这张日志表上
却不生效 —— 纯 DOM 插入、余量充足、祖先链无 `none` 的情况下仍不补偿，
且已排除固定列 sticky、table-layout、`overflow: hidden` 三种因素。

### 新日志扫光

新行插进来时，沿这一行的下分割线从左扫过一道彩虹（约 2 秒，见
`docs/ui-spec.md` 第 11 条）。只有实时推送带来的新行会闪：刷新页面、改筛选、
翻页、点「刷新」都不闪，系统开了「减弱动态效果」时也不闪。亮带画在表格外面的
独立一层里，**不往表格里加任何元素** —— 往 `tr` 里放伪元素会让 Chrome 在
`table-layout: fixed` 下不再分配多余宽度，整表塌回声明宽度、右侧空出一条
（只在窗口比表格宽时出现，2026-09-16 修）。

### 表格里几处「差几像素」的规格

- **两排数值的列左缘对齐**：「词元」「任务耗时」两格里的内容块居中，但轨道
  宽度写成了定值 —— `auto` 轨道会跟着数值长短伸缩，整块宽度逐行不同，竖条和
  图标因此每行落在不同的 x 上（宽窗口实测漂 7.2 / 9.38px）。定值取「列最窄时
  可用宽度」倒推，任何窗口下都不会溢出（见 `docs/ui-spec.md` 第 10 条）。
- **任务耗时的双色竖条**：竖条断成两段，上段跟「首字」、下段跟「耗时」，
  段色各自继承该行数值的 `currentColor`。首字 ≤10s 绿 / 10-30s 橙 / >30s 红，
  耗时 ≤20s 绿 / 20-60s 橙 / >60s 红 —— 两行各用一套阈值（首字才是「卡不卡」
  的那一下，总耗时含上游生成本来就长）；一整条单色只能表达「这次调用慢」，
  断成两段才看得出慢在哪一段。秒值一律补齐两位小数（`8.70s`），
  不足 1 秒仍按毫秒显示（见 `docs/ui-spec.md` 第 6 条）。

### 默认模型映射（兜底）

每条渠道可单独开启，指定一个白名单里的模型。开启后，**白名单没精确命中的
请求**一律改用这个模型发往上游；精确命中的仍按白名单走（精确优先，兜底候选
永远排在最后）。这是为 Claude Code 这类自己挑模型名的客户端准备的：它发来的
`claude-sonnet-4-6` / `claude-opus-4-7` 不在任何渠道白名单里，从前会得到
耗时 1–3ms、token 全 0 的 502（模型名原样转发给上游，被上游当场拒绝）。
开了兜底就不必每次回来改白名单。三件事要知道：

- **日志里请求模型仍记客户端的原名**，上游模型记实际发往上游的名字，并带
  「兜底」标记 —— 开启了兜底之后**模型名写错也不再报错**，这个标记是发现
  「其实没命中」的唯一途径。兜底目标行配了「对外名 → 上游名」映射时，映射
  照常生效（2026-09-21 修复：此前映射被忽略，上游收到它不认识的对外名，
  复现兜底要消灭的那种 502）。
- **费用按兜底目标的单价计算**（客户端的模型名在渠道里通常没配价）。
- **响应里的模型名是上游回显的那个**（即兜底目标），不是客户端请求的名字 ——
  这是**既有行为**，与兜底无关：任何配了「上游模型名」的渠道都这样（响应改写器
  优先取上游响应体里的 model 字段，取不到才回落到请求名）。客户端拿到一个
  与自己请求不同的模型名是预期内的。

另：**密钥的 `allowed_models` 白名单不被兜底豁免**（配了限制就仍然 403，
不会被兜底绕开）；兜底目标必须是该渠道白名单里**启用中**的条目 —— 保存时拦
（目标行停用也拦，2026-09-21 起），分两步造出的半残（先配好、事后停用那一行）
由失败提示点名、渠道列表的「兜底」胶囊不亮；**备份导入**带进来的半残配置会被
剥离并写进导入报告。

### 故障转移细节

- 上游返回任何非 2xx 状态码都立即切到候选链的下一个渠道；客户端主动断开
  （手动结束推理）除外 —— 收件人已不在，换渠道重发没有意义，也不会把这种
  失败记到渠道头上。
- 429 按 `Retry-After` 冷却（上游给了 `Retry-After` 或 503 时以它为准，封顶
  8 秒）、401/403 冷却 30 秒；413/414/431（请求物理尺寸超限）第一个渠道就
  短路返回，不再空试。
- 一次转发中多个渠道报出相同的请求形状类 4xx（如都 400）时判定为请求级错误，
  不记渠道失败；渠道连续失败 3 次自动冷却 60 秒，成功一次即恢复。
- 换渠道前若**下一个候选仍打在同一台上游**（两条渠道共用同一个 `base_url`），
  先等 `RELAY_RETRY_SAME_UPSTREAM_DELAY`（默认 500ms，可设 0 关闭）——
  零间隔连打同一端点会被上游当成攻击，正是熔断的诱因；换到别的上游则不等，
  那不会给谁造成压力。

### Tool Search（advanced-tool-use-2025-11-20）的兼容口径（2026-10-20）

Claude Code 2.1.299 的「工具搜索」把 MCP 工具的 schema 从首轮请求里拿掉：
`tools` 只剩内置工具加一个 `DeferredToolPlaceholder`（带 `defer_loading: true`），
MCP 工具名以纯文本列在 system prompt 里。模型先调客户端侧的 `ToolSearch`，
客户端本地检索后把完整 schema **仍带 `defer_loading: true`** 塞回 `tools`，
并在 `tool_result.content` 里放 `{"type":"tool_reference","tool_name":"..."}`。

搜索、匹配、schema 返回全在客户端完成，中继**不实现任何检索逻辑**，只负责
「不破坏协议」。四条落点：

- **beta 头不校验**（`relay/forward.go` 的透传段）：Anthropic 渠道整串原样转发，
  非 Anthropic 渠道干脆不发。不做「已知 beta」白名单 —— 能用的 beta 随上游版本
  滚动，白名单必然滞后，而拦下未知 beta 的代价是客户端 400 且**不会自动降级**
  （实测 Claude Code 会原样重试一次，然后把错误抛给用户）。
- **`defer_loading` 保留/丢弃**（`convert/anthropic.go` 的 `deferLoadingKey`）：
  入站抄到通用语工具条目顶层暂存，出站还是 Anthropic 时写回（`openAIToolsToAnthropic`），
  其它上游由 `stripCacheControl` 清掉。少了这条，Anthropic→Anthropic 链路上的
  `defer_loading` 会在通用语里蒸发，占位工具与已解锁工具的行为一起漂移。
- **`tool_reference`**（`flattenToolResult` + `anthropicToolResultKey`）：通用语里
  降级成一行 `[Tool loaded: <tool_name>]`（给 OpenAI 兼容上游的提示）；同时在 tool
  消息上暂存原始数组，出站 Anthropic 时原样还原 —— 结构化引用不该被改写成自然语言。
  非 string 的 `tool_result.content` 本来就是正常输入（多模态数组早已支持），不拒绝。
- **不去重**（需求方明确要求）：同名工具两条、其中一条带 `defer_loading` 时两条都保留，
  `convert` 里没有提供任何按名字合并的逻辑。

回归：`convert/tool_search_test.go`（9 条用例）、`relay/forward_headers_test.go`
（beta 整串透传）、`scripts/test-upstream-protocol.sh` 第 7 节（真机链路，
判据取自 mock 上游记录的 `last_request` 原文）。

### `/v1/models` 的思考档位声明（2026-10-21）

每个模型条目带 `supported_efforts`（`off/auto/minimal/low/medium/high/xhigh/max`），
回答的是「客户端对**这个模型**能安全发哪些思考档位」。两点决定性设计：

- **数据挂在白名单行上**（`channel_models.supported_efforts`，jsonb），不是另建
  能力表：同一个模型名在不同渠道背后可能是不同上游（官网直连 vs 中转站），
  「支持哪些档位」本来就该跟着渠道走 —— 与价格挂在这一行是同一条理由。
- **空 = 没配，回落到按渠道协议推导**（`relay.SupportedEfforts` →
  `convert.EffortsForProtocol`）。推导的依据是 `thinking_map.go` 里已有的**出站
  映射**，不是另拍的一套：Anthropic / Gemini 八档全在（off→disabled、auto→adaptive，
  其余按 effort 或 budget）；OpenAI Chat / Responses / custom 只列
  `low/medium/high/xhigh/max` —— 实测 `off`/`auto` 发过去 400（见
  `stripUnsupportedEffort`），`minimal` 只能向上收敛成 `low`，把它们写进声明
  等于承诺一条会报错的路径。embeddings 没有思考概念，回 `[]`。

同名模型挂在多条渠道上时取**并集**（`relay.MergeModelEfforts`）：请求最终只落在
一条渠道上，只要有一条能表达这个档位，它就有意义。顺序由
`convert.NormalizeEfforts` 收成强度序，不按渠道遍历顺序。

写路径：后台白名单编辑器的「档位」一列（多选，`components/efforts.ts`），
经 `whitelistItem.supported_efforts` 提交；`normalizeWhitelist` 归一后落库，
空数组与没传都归一成 NULL。单条绑定接口（`bindChannelModel`）用指针区分
「这次不动它」与「显式清空」，避免空载荷把已配的档位抹掉。备份导入同样过归一。

两边的一致性由 `scripts/check-contracts.mjs` 的「档位词表前后端一致」静态比对
兜住（前端 `EFFORT_LEVELS` 与后端 `convert.AllEfforts` 必须逐项相同：前端词表
在 `relay/convert` 包里，tygo 只生成 `internal/model`，没法自然共享）。
回归：`convert/thinking_map_test.go`、`relay/thinking_test.go`、
`api/model_efforts_test.go`（后者的 `/v1/models` 用例连库，钉住「空能力回 []
而不是 null」与停用行/渠道/分组的过滤）。

### 密钥 → 分组的强一致引用

密钥白名单里存**分组 ID**（与渠道的 `group_id` 同一待遇），保存时逐条校验
存在性 —— 分组改名不再打断任何密钥（曾经白名单存分组名，改名即全体 403，
界面上毫无征兆）；删除分组前检查密钥引用，仍被引用时 409 并点名密钥。
`/v1/models` 同时按密钥的**模型白名单**过滤 —— 客户端探测到的就是它能调的，
不会选一个就被 403 一次。老数据在启动时自动迁移（名字条目换算成 ID，幂等；
解析不了的保留原样并在日志里点名）。

### 前端两条硬约定（2026-10-10 打磨时立）

两条都是「值只有一个出口」的约定，都由 `frontend/scripts/check-contracts.mjs` 钉住，
写错了 `npm run check` 会直接红并告诉你该用什么：

1. **文字颜色只用 `--text-*`，`--color-*` 只用于填充/边框/图标。**
   `--color-*` 那一组是按 WCAG 1.4.11 的非文本阈值（3:1）挑的，
   直接拿来当正文色会掉到 2.15~3.90:1（2026-10-10 审出 11 处，最低的
   `--color-orange` 压白卡只有 2.15:1）。需要「主色系的文字」时用
   `--text-primary-ink`、语义色用 `--text-amber` / `--text-green` / `--text-red` 等，
   实心块上的文字用 `--solid-primary-fg`。守卫的判据是组件里
   `color:` / `-webkit-text-fill-color:` 的值中出现那 7 个语义色令牌即失败，
   报错时会算出各主题的实测对比度；确需例外就在行尾写
   `/* text-token-exempt: <理由> */`。
2. **弹窗 / 抽屉宽度只用 `utils/modalWidth.ts` 的 `modalWidth(N)`。**
   它会拼成 `min(Npx, 94vw)`，窄窗口下不会被顶出视口。守卫断言每个
   `a-modal` / `a-drawer` 的 `:width` 都来自它、且模板里不许再出现字面 `vw`。

另外两条同批次的收口：响应式断点只能用 `theme.css` 注释里那张刻度
（640 / 768 / 1024 / 1200 / 1536，900 只作为侧栏折叠的 JS 功能断点存在），
守卫会逐个 `@media` 比对；轻提示与确认弹窗一律从 `@/utils/feedback` 引入
（`message` / `modal`），**不要**再用 antd 的静态方法 —— 静态方法拿不到
`<a-config-provider>` 的令牌，深色主题下会渲染成浅色默认皮肤。

第二批（同日）再加三条：

3. **字号只用 `var(--font-size-*)`，组件里不许写字面 px。**
   刻度定义在 `theme.css` 的 `:root`（那一段注释解释了 lg/xl 为什么夹在正文
   之间），`check-contracts.mjs` 的「字号刻度契约」会拦字面量。
4. **表格列显隐走 `useColumnVisibility` + `ColumnSettings`。**
   存的是「被隐藏的列」而不是「显示的列」（加新列时默认可见）；
   有测量的表格（日志表）关列后要同步三处：模板 `v-if`、`scroll.x` 的合计、
   以及余量分摊的列集合（`allocateWidths` 的 `keys` 参数）。
5. **移动端形态用 `railMode` 判断，不要用 `collapsed`。**
   `collapsed` 是「900px 以下的图标栏」，`railMode = collapsed && !isMobile`
   才是「真的只剩图标」；≤640 时侧栏是抽屉（`is-mobile` / `is-open` /
   `inert`），模板里所有「收起态不显示文字」的判断都该看 `railMode`，
   否则抽屉里会没有文字菜单。断点状态用 `composables/useMediaQuery(query)` 取
   ——别各写一遍 matchMedia 样板，那四步里最容易漏掉卸载时的监听清理。
   窄屏改动前先跑 `.shots/probe-mobile.mjs` 量证据。

### 主题系统

2026-09-30 起界面有 **12 套内置配色**（浅色 4 / 深色 8），入口是**数据看板工具栏
右上角那枚按钮**（点开是一个主题网格弹层）与**系统设置页的「界面主题」面板**
（同一个选择器组件，两种尺寸）。原来的「深色质感档位」（`data-darkstyle`）已取消，
「深空纯黑」升格成一套普通主题；老键在 store 里做一次性迁移。

一条轴：`<html data-theme="<主题 id>">` 就是全部状态。`styles/theme.css` 里
`:root` 是 `light` 主题本尊，其余 11 套各是一个 `:root[data-theme='<id>']` 块，
**每块把随底色而变的令牌写全**（清单见 `frontend/scripts/lib/theme-css.mjs` 的
`REQUIRED_TOKENS`）—— 不许靠继承：漏一个令牌会静默继承浅色主题的值，
不报错、不失败，只是某个字在某套主题下发虚。哪些 id 存在由
`src/utils/themes.ts` 的注册表说了算。

配色来源（都是 MIT 许可，偏差逐条记在各自主题块的注释里）：

| 主题 id | 上游 | 主题 id | 上游 |
|---|---|---|---|
| `light` / `dark` | 参考站 llm.ohub.vip 实测 | `nord` | Nord |
| `oled` | 本站扩展（深灰的表面换纯黑） | `dracula` | Dracula |
| `latte` / `mocha` | Catppuccin Latte / Mocha | `tokyo-night` | Tokyo Night |
| `solarized-light` / `solarized-dark` | Solarized | `gruvbox-light` / `gruvbox-dark` | Gruvbox |

取色规则：表面三件套与主色逐字取上游官方色值；上游没有中间调边框色时允许
在两端色之间做 sRGB 插值（注明比例）；**上游值达不到 WCAG AA 就改**，
偏差必须记进注释 —— 这不是例外而是常态（Solarized Light 的官方正文只有 4.15:1、
Solarized Dark 的 base0 只有 4.32:1、Dracula 的正红在深色卡片上只有 3.6:1）。

三条守卫：

- `frontend/scripts/check-theme-contrast.mjs`：逐套实算 WCAG 比值
  （文字 ≥ 4.5:1、非文本 ≥ 3:1、边框 ≥ 1.15:1），并打 INFO 提示「族档位令牌
  在族内取值不一致」（可能是某个主题有意微调，也可能是改了一套忘了另一套）；
- `frontend/scripts/check-contracts.mjs` 的「主题契约」一节：注册表 / CSS 块 /
  `index.html` 预涂清单 / 预览色样 / 光标资源 / antd 令牌映射六处一致性，
  外加一条漂移守卫 —— **组件里不许出现 `[data-theme=…]` 选择器**
  （多主题下那种分支要么漏 10 套主题，要么每加一套都要回来改）；
- `scripts/verify-themes.mjs`：真浏览器逐套确认「声明有没有真的作用到页面上」
  （属性、页面底色、浏览器外壳色、刷新保持、弹层点击、控制台无异常）。

antd 的令牌（主色、语义色、背景、边框、文字灰阶）**不再在 `App.vue` 里手抄**：
`src/utils/antdTheme.ts` 维护「antd token → CSS 变量」的映射，运行时从计算样式读取。
12 套主题 × 13 个值手抄就是 156 份会各自漂移的副本，而漂移的表现是
「按钮颜色和卡片不是同一套主题」，不报错、不失败。

**新增一套主题的步骤**（缺一步 `npm run check` 就会报出来）：

1. `styles/theme.css`：复制一个同族主题块，改值，注释写清上游色名与偏差
   （比值先跑 `node scripts/check-theme-contrast.mjs --verbose` 看实测）；
2. 同一文件末尾的 `[data-swatch='<id>']` 加四项预览色（页面底/卡片/边框/主色实心块）；
3. `src/utils/themes.ts` 的 `THEMES` 加一项（id / 名字 / 上游 / 明暗 / 说明 / 外壳色）；
4. `frontend/index.html` 预涂脚本的 `THEME_IDS` 数组加一项（漏了会「刷新闪一下」）；
5. `cd frontend && npm run gen:cursors` 生成该主题的两个光标文件（提交入库）；
6. `npm run check && npm run test && npm run type-check`，必要时跑
   `node scripts/verify-themes.mjs <base> <新 id>` 单独确认这一套。

### 自定义光标

鼠标光标是本项目自己的品牌元素（参考站没有）：默认箭头与交互手型**每个主题
各有一套**，22 份图形在 `frontend/public/cursor-{arrow,hand}-<主题 id>.svg`。
两族的**形状**不同（浅色是长而窄的锐角轮廓、深色是短而阔的圆角轮廓），
颜色取自各主题「主色实心块」的那一对变量（填充 = 块底色、描边 = 压在上面的文字色）。

只有 `light` / `dark` 那四份是手写的（它们就是形状模板，正文里记着尺寸实测）；
其余 18 份由 `frontend/scripts/gen-theme-cursors.mjs --write`（`npm run gen:cursors`）
从对应族的模板重着色生成 —— 光标是当图片加载的、没有 CSS 级联，SVG 里写不了
`var()`，颜色只能是字面量，11 套主题手抄一份必然漂，而且漂了没有任何报错。
`--check` 模式与 `check-contracts.mjs` 会逐字节比对，所以「改了主题主色、
忘了重新生成光标」会当场变红。`oled` 复用 `dark` 的两个文件
（实心块那一对相同，注册表里用 `cursorSource` 显式声明）。

所有主题的热区坐标（箭头 `2 2`、手型 `9 2`）必须逐字相同，否则切主题时点击
落点会跳。输入框 I 型、拖拽、禁用、帮助四类保留系统光标。

要改光标形状或补齐 antd 升级后新增的交互组件，看
`frontend/src/styles/theme.css` 的「自定义光标」段 —— 那里记着清单的来源、
为什么必须 `!important`、为什么文件名带主题后缀（这几个资源没有
ETag/Last-Modified，缓存只能靠 URL 判断），以及 `npm run check` 里盯住哪几条。
形状的生成/核对工具在 `.shots/`（不入库）：`gen-cursor-dark.mjs` 生成深色路径、
`measure-cursors.mjs` 用浏览器 `getBBox()` 量实际尺寸、`contrast.mjs` 算对比度
—— 注释里引用的数字都出自这三个脚本。

### 在 Windows 上跑这些脚本：`scripts/wsl-bash.psm1`

这些脚本都在 WSL 里跑，而从 Windows PowerShell 直接调 `wsl` 会把三层解析
（PowerShell → wsl.exe → bash）的坑同时引出来。这个模块把它们一次解决：

```powershell
Import-Module .\scripts\wsl-bash.psm1

# 跑脚本文件（推荐）：内容由 bash 直接读，中文与各种引号都不需要转义
Invoke-WslScript -Path .\deploy\install.sh

# 跑一条内联命令：**用单引号**，避免 PowerShell 先做变量插值
(Invoke-WslBash -Command 'systemctl is-active llm-relay').Output
```

| 坑 | 症状 | 解法 |
|---|---|---|
| wsl.exe 的输出编码 | 每次调用都刷一屏乱码 | 模块设 `WSL_UTF8=1`；**不要**靠重定向 stderr 了事（会把真报错一起丢掉） |
| 那条固定的 localhost 代理警告 | 混进输出，干扰解析 | 模块按前缀丢弃**这一条**已知噪音，其余 stderr 全部保留 |
| PowerShell 双引号会插值 | `"$HOME"` 在送到 bash 前就被替换成空串 | 内联命令一律用**单引号**；`$(...)`、反引号、`$` 在单引号里都是字面量 |
| Windows 路径不能直接给 bash | `bash C:\foo.sh` → 127 | 模块用 `wslpath -u` 转换（不要手拼 `/mnt/c/...`） |
| `Set-Content` 写 CRLF/BOM | `bash: $'\r': command not found` 或 shebang 失效 | `New-WslScript` 按 LF + UTF-8 无 BOM 写，并 `chmod +x` |
| `-lc` 会读 ~/.profile | 启动文件可能污染退出码（命令成功却是 1） | 模块用 `-c` 起干净的非登录 shell |

### 光标审计：`scripts/audit-cursors.mjs`

需要先起一个带调试端口的 Chrome（用法见文件顶部）：把七个路由连同弹窗、
抽屉、下拉里每个元素的**计算光标**统计一遍，确认没有一处退回系统光标。
它存在的理由很具体 —— **CSS 的 cursor 不进截图**，少写一个选择器、antd 升级
换了 class 名、光标图片 404，表现都只是那一处悄悄变回系统箭头，不报错也不失败：

```bash
node scripts/audit-cursors.mjs http://127.0.0.1:5173   # 开发态
node scripts/audit-cursors.mjs                          # 默认打 127.0.0.1:8888
node scripts/audit-cursors.mjs http://127.0.0.1:8888 light        # 只审浅色
node scripts/audit-cursors.mjs http://127.0.0.1:8888 all          # 全部 12 套（慢）
node scripts/audit-cursors.mjs http://127.0.0.1:8888 solarized-dark   # 点名一套
```

默认跑两套默认主题（浅色 / 深色），`all` 跑全部 12 套。每个用例靠预置
`localStorage` 里的 `llm-relay-theme` 切主题，导航前注入，所以首屏那批元素也在
审计范围内。**页面上出现任何「不是本主题那一套」的文件名都判失败**，单独归为
「串主题」一类打印 —— 只检查「是不是自定义光标」的话，某个主题漏配光标令牌时
会继承 `:root`（浅色）那套，审计报告会一模一样全绿，而「绿得看不出区别」的检查
等于没检查。这条判断本身有反向验证：`.shots/verify-cross-theme-detection.mjs`
会手动把深色页面的光标变量改写成浅色那套，确认审计真的报出串主题的元素。

2026-09-30 起主题清单与期望文件名都从 `frontend/src/styles/theme.css` 解析
（`frontend/scripts/lib/theme-css.mjs`，与前端几个脚本共用一份解析器）：
硬编码 `['light','dark']` 的话，新增主题不会自动纳入审计，而「忘了加」
在这类脚本里是完全静默的。

### 主题端到端：`scripts/verify-themes.mjs`

静态脚本能比对声明，但「声明有没有真的作用到页面上」只有渲染后才知道：
选择器写错、属性拼错、打包没带上，表现都只是页面退回默认配色，不报错。


等于主题块声明的值、`meta theme-color` 等于注册表里的外壳色、导航期间控制台无异常；
然后用**真实鼠标事件**点开看板那枚按钮，确认弹层里有全部主题卡（且分成浅色/深色
两组）、点一张卡真的换主题、弹层不自动关闭、刷新后仍是刚选的那套、快捷按钮
能切回浅色族。截图落到 `.shots/theme-<id>.png`（不入库，用来肉眼确认配色观感）。

### 表格列宽守卫：`check-table-widths.mjs` 与 `check-log-columns.mjs`

列宽 2026-09-23 起由脚本按当前页内容量出来（见 `docs/ui-spec.md` 第 17 条），
于是「列宽对不对」不再能从源码里一眼看出来：

- **check-table-widths.mjs**（静态，不需要浏览器）：每个表的 `scroll.x` 与各列
  声明宽度要对得上。运行时表（列宽来自 `colW`）它查的是「**每一列都绑了那个
  表达式**」—— 混进一个裸数字，那一列就不会随测量联动，表现为它永远停在声明
  值上。这个脚本此前只认数字字面量，请求日志表改成 `colW.xxx` 之后**整张表被
  静默跳过**，「没报错」于是被读成「没问题」，所以现在它会把「跳过」明确打出
  来并给出退出码；
- **check-log-columns.mjs**（需要调试端口的 Chrome）：静态检查只能确认「测量
  代码接对了」，而「量出来的宽度是否真的装得下内容」只有渲染后才知道 —— 这类
  问题不报错，内容被省略号截掉、页面一切正常。它按「3 视口 × 3 种每页条数」
  逐格断言三件事：锚点元素没有溢出（内容没被截断）、单元格自身没有横向溢出、
  横向滚到最右端时右侧固定列不遮挡内容。每页条数是从源码读出的 localStorage
  键名写进去的，并断言行数真的等于这一轮的 pageSize —— 否则整套矩阵会跑在同
  一个行数上，看着全绿其实只测了一种（第一版就是这么错的）。

```bash
node scripts/check-table-widths.mjs                                # 静态，秒出
node scripts/check-log-columns.mjs                                 # 默认 3 视口 × 20/50/100 条
node scripts/check-log-columns.mjs http://127.0.0.1:8888 1440 20   # 单组合
```

## 发布流程（本仓库维护者）

**发布 = 一条命令。** 服务器侧没有「部署」这个动作 —— 实例通过自动更新
自己拿新版本，人只负责把版本号命名出来：

```powershell
pwsh -File scripts/release.ps1 patch     # 或 minor / major / v0.1.5 / --dry-run
```

（Linux/macOS 直接跑 `bash scripts/release.sh`，两者同一实现，ps1 只是
Windows 侧把 gh 的 PATH 拼好再转发。）

脚本依次完成：前置检查（main 分支、工作区干净、gh 已登录）→ 本地预检
（go vet/test、前端 type-check 与契约检查 —— release.yml 会再跑一遍，
这里先跑是把失败拦在打 tag 之前，tag 一推就是「已发布」状态，不可收回）→
按 semver 递增算出新版本号 → 推送 main → 打 tag 推送（触发流水线）→
`gh run watch` 观察到全部 job 结束 → 验证 Release 归档与 checksums.txt
真的在场（归档名是安装脚本与在线更新拼下载 URL 的硬契约）。

发布完成后，服务器上**不需要任何操作**：

```
管理台 → 系统设置 → 版本更新 → 检测更新 → 一键更新
（下载归档 → sha256 校验 → 原子替换 → systemd 拉起，约 1-2 分钟）
```

发布之后不必自己去点「检测更新」：服务端**每 5 分钟**自己检测一次
（`update.StartCheckLoop`，见 `internal/update` 里 `BackgroundCheckInterval`
的说明；进程启动一分钟后开始），结果写进与手动检测同一份缓存，
侧栏版本徽标跟着 5 分钟问一次自己的后端（命中缓存，不打 GitHub），
所以新版本发布后最多十几分钟徽标上就会出现黄点。观察这一环：

```bash
journalctl -u llm-relay -f | grep -E '后台版本检测|检测到新版本'   # 启动一行 + 发现新版本时一行
```

日志刻意只记「事件」（首次就绪 / 发现新版本 / 开始失败 / 恢复成功）：
国内直连不通 GitHub 要靠代理是常态，每 5 分钟一条失败 WARN 会把真正重要的
日志淹掉。

也可以手工打 tag（脚本做的事等价于）：

```bash
git tag -a v0.1.2 -m "v0.1.2" && git push origin v0.1.2
```

tag 触发 `.github/workflows/release.yml`，它会：

1. 跑测试，并把版本号写进 `backend/internal/version/VERSION`；
2. 用 goreleaser 构建 5 个平台的归档（含 `rotate-secret` 工具）
   + `checksums.txt`，创建 Release；
3. 把 `VERSION` 回写到主分支，让下次构建的兜底版本号跟上。

产物命名是硬契约，`deploy/install.sh` 与在线更新按它拼下载地址：

```
llm-relay_<版本>_<系统>_<架构>.tar.gz     # windows 用 .zip，版本号不带 v
  └── llm-relay / llm-relay.exe          # 归档内的主可执行文件
  └── rotate-secret                      # 主密钥轮换工具（linux 归档）
  └── deploy/                            # install.sh / restore.sh / .env.example
checksums.txt                            # sha256，两空格分隔
```

也可以在本机试跑：`make release-snapshot`（需先装 goreleaser）。
