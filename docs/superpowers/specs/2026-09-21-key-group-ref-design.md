# 密钥 → 分组的强一致引用

日期：2026-09-21
状态：已实现

## 背景

站主反馈「分组管理、渠道管理、密钥管理有些不协调」。逐层核对后发现不协调的
根源是**引用方式不对称**：

| 关系 | 存储 | 写入校验 | UI 输入 | 分组改名 / 删除的连带 |
|---|---|---|---|---|
| 渠道 → 分组 | 外键 `group_id` | 创建/更新都预检 | 受控下拉 | 无感 |
| 密钥 → 分组 | 字符串列表，存**分组名** | 完全不校验 | 自由 tags 输入 | 改名 → 该密钥全体 403；删除 → 悬空引用 |

三个连锁问题，每个都可实测触发：

1. **分组改名 = 打断密钥**。`resolveGroupWhitelist` 按名字查库，改名后旧名进
   `unresolved`，而它的策略是部分失败也整体报错 —— 引用它的密钥**所有请求**
   403，哪怕客户端调的模型在别的分组。
2. **分组删除留下悬空引用**。`deleteGroup` 只检查渠道占用，密钥白名单不查、
   不清、不提示。
3. **打错字静默入库**。创建/更新密钥不校验白名单，`"生产"` 打成 `"生厂"`
   也能保存成功，直到调用 403。

顺带核出两个同源问题：

- `/v1/models` 只按分组白名单过滤、不按模型白名单过滤（它自己的注释写着
  「否则客户端会看到一堆自己调不了的模型」，理由只落实了一半）；
- `RelayRequest.GroupID` 是死参数：生产链路（relay_handler 构造）从不设置，
  `noChannelReason` / 提示查询里的 GroupID 分支全是死代码。

## 决策

| 决策 | 取值 | 理由 |
|---|---|---|
| 存储形态 | 分组 ID 的十进制字符串 | 保持 StringList（jsonb）类型，老数据（名字）与导入备份可平滑迁移；`resolveGroupWhitelist` 的双轨解析（ID/名字）保留作运行期兜底 |
| 写入校验 | 创建与更新都逐条预检，失败即 400 | 与渠道接口的 `checkGroupExists` 对称；保存时发现比调用时 403 便宜 |
| 前端输入 | 受控多选（`mode="multiple"`，值为 ID） | 与渠道表单的分组下拉同一范式；自由输入是打错字的入口 |
| 老数据迁移 | 启动时名字 → ID，幂等 | 解析失败的名字**保留原样**（删掉 = 静默放宽权限），只留 Warn 日志 |
| 分组删除 | 渠道占用、密钥引用两道守卫，均 409 | 自动清理密钥引用 = 静默放宽权限，与「密钥白名单不被兜底豁免」同一哲学 |
| `/v1/models` | 内存过滤，复用 `modelAllowed` | 判据必须与 403 拦截处同一份；两处各写一个查询迟早漂移 |
| 死参数 | `RelayRequest.GroupID` 删除；`CandidateQuery.GroupID` 保留 | 前者是业务 DTO 上的死字段；后者是 router 引擎的查询能力、有测试覆盖，注释里说明现状 |

## 实现

- `api.normalizeGroupRefs` / 纯函数核心 `normalizeGroupRefList`：去空白、名字换
  ID、去重、失败即报错（`key_group_refs_test.go` 锁规则）
- `store.normalizeKeyGroupRefs`：一次性迁移，挂在 `Migrate()` 的 AutoMigrate 之后
- `deleteGroup`：`allowed_groups @> '["<id>"]'::jsonb OR @> '["<名字>"]'::jsonb`
  —— 名字形态也要匹配，漏掉它守卫对老库形同虚设；jsonb 参数化顺带堵死注入
- `listModels`：Pluck 之后按 `key.AllowedModels` 过滤
- 前端 `KeysView`：多选存 ID；列表列 ID → 分组名解析，悬空引用显示红色虚线
  胶囊 + tooltip 说明后果；编辑老密钥时名字条目就地换成 ID

## 验证

- 单元：`TestNormalizeGroupRefList`（归一化六规则 + 失败必报）
- 端到端：`scripts/test-key-group-refs.py`（归一化回显、400、/v1/models 过滤、
  删除守卫、清引用后可删），已挂进 `verify-all.sh`
- 迁移实效：部署前线上有一把白名单为 `["DeepSeek"]`（名字形态）的密钥，
  部署重启后库中变为 `["20"]`（该分组的 ID）—— 见部署记录

## 不做的事

- 不给密钥白名单建真外键列（`int[]`）：jsonb StringList 是既有类型，改类型要
  处理混合老数据的读取，复杂度不成比例；写入侧归一化 + 删除守卫已关上主要口子
- 不在分组改名时联动改写密钥里的名字：迁移到 ID 后此问题不存在
- 不自动清理悬空引用：静默放宽权限比 403 更危险（与密钥模型白名单不豁免同判）
